# ZG01 Control GUI v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `zg01-control`, a Rust/GTK4 desktop application that opens on a live mixer, exposes the mic chain, loads `.zgpreset` files, and ships as its own package from the `snd-zg01` monorepo.

**Architecture:** A Rust workspace with `zg01-core` (ALSA, model, units, layout, writer, meters, device watcher, preset FFI) and `zg01-gui` (relm4 app, custom fader/meter widgets, Mixage/Micro/Avancé screens). ALSA control names are the contract; missing controls hide their widgets. A worker thread serialises and coalesces writes so the GTK main loop never blocks on USB. Presets reuse the C parser and the generated control map from `feat/zgpreset-controls`; no second parser.

**Tech Stack:** Rust, GTK4, libadwaita, relm4, `alsa` crate, `serde`/`toml`, `cc` (FFI build), gettext, GNU Make, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-31-zg01-gui-design.md`

## Global Constraints

- v1 scope: Mixage, Micro, Avancé, presets, packaging. Jeu, Casque, Réglages, compact meters and PipeWire levels are v1.1.
- The application is dark-only in v1. All colours come from the token table in the spec (`#14161b`, `#1b1e26`, `#272b35`, `#eef1f6`, `#c9b8ff`, `#8b6ff0`, `#34c759`, `#f0b429`, `#f0523b`).
- Control names are exact and stable. Missing controls are hidden, never fatal.
- Stream and monitor levels are 0–127 steps. Only `... Gain` controls use 0.1 dB; frequency is Hz; Q is 0.01.
- Unit conversions must match `src/zg01_control.c` exactly. The Rust port is tested against the driver's conversion table.
- The GUI never claims to read the device state. Startup reads the driver cache; Reset marks every writable value unknown and disables Save.
- Preset raw gating uses `provenance == "raw"` (53 addresses), matching `zgctl preset load --allow-raw`. A `Steps` suffix is not a raw marker.
- Only `.zgpreset` is loadable. `.zg01` backups are rejected with a clear message.
- No second `.zgpreset` parser: the GUI links `tools/zgpreset.c` through `cc` and reads `tools/vendor/control-map-zg01.json` at build time.
- No root. The app talks to ALSA as the user.
- `cargo test`, `cargo clippy -- -D warnings` and `cargo fmt --check` pass in CI.
- Source lives in `gui/`; the package is separate (`snd-zg01-gui`, Arch `zg01-control-git`); GUI tags are `gui-vX.Y.Z`.

## Review Focus

- A missing ALSA control (older driver) must hide its widget, never panic or show a fake value.
- A failed write must revert the optimistic value and surface the error; the UI must stay responsive while USB blocks.
- Reset must mark values unknown and disable Save; loading a preset or writing a control makes them known again.
- A preset with raw, out-of-range, read-only or unknown addresses must be reported and skipped, never clamped or silently applied.
- Disconnect/reconnect during a write or meter poll must not panic, hang, or write to a stale card index.

```rust
use std::sync::{Arc, Mutex};
use std::time::Duration;
use zg01_core::alsa::{AlsaBackend, AlsaError, ControlInfo};
use zg01_core::writer::ControlWriter;

#[derive(Default)]
struct RecordingBackend {
    writes: Mutex<Vec<(String, i64)>>,
}

impl AlsaBackend for RecordingBackend {
    fn list_controls(&self) -> Result<Vec<ControlInfo>, AlsaError> { Ok(vec![]) }
    fn read(&self, _name: &str) -> Result<i64, AlsaError> { Ok(0) }
    fn write(&self, name: &str, value: i64) -> Result<(), AlsaError> {
        self.writes.lock().unwrap().push((name.into(), value));
        Ok(())
    }
}

#[test]
fn coalesces_to_the_last_value() {
    let backend = Arc::new(RecordingBackend::default());
    let (writer, _rx) = ControlWriter::spawn(backend.clone());
    for value in 1..=10 {
        writer.set("Gate", value);
    }
    std::thread::sleep(Duration::from_millis(100));
    assert_eq!(*backend.writes.lock().unwrap(), vec![("Gate".into(), 10)]);
}
```

Add a second test: a backend that returns `Err` produces one `WriteOutcome::Err`.

- [ ] **Step 3: Implement the workers**

The writer thread keeps a `HashMap<String, i64>` of pending values and
flushes every 20 ms (or on a small batch), writing the last value per
control. It never runs on the GTK thread. The meter poller reads the six
`METER_CONTROLS`; a missing control becomes `None`, not zero. The
watcher compares consecutive `presence()` results and emits only
transitions.

- [ ] **Step 4: Implement the plan and apply**

The plan resolves each address through the control map:
- missing control → `Skipped::Missing`;
- `writable == false` → `Skipped::ReadOnly`;
- `provenance == "raw"` and not allowed → `Skipped::Raw`;
- converted user value outside the ALSA control's `info.min`/`info.max`
  (user units, not the map's device bounds) → `Skipped::OutOfRange`;
- otherwise `Apply { name, user_value }`.

The apply step writes each `Apply` through the `ControlWriter` and
reports the outcomes. It does not call Save.
