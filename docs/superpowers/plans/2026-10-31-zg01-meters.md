# ZG01 Meter Controls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Decode the ZG01's 192-byte meter frames and expose four read-only, volatile ALSA controls that userspace can poll at 20 Hz. GAME and HDMI are documented as undecoded; their names stay reserved.

**Architecture:** A Python reference decoder settles the byte map from usbmon captures. The driver runs a bulk IN URB chain on endpoint `0x83`, parses meter frames with a pure header-inline function, stores atomic snapshots, and registers four integer kcontrols with `READ | VOLATILE` access. The control write path on `0x03` is untouched.

**Tech Stack:** C (kernel module), Python 3 (reference decoder and fixtures), shell tests, ALSA control API, usbmon captures.

**Spec:** `docs/superpowers/specs/2026-10-31-zg01-gui-design.md`

## Global Constraints

- Meter frames are 192 bytes on bulk IN `0x83`, starting with `04 f0 43 10 | 04 3e 14 02`, roughly every 50 ms.
- The registered control names are exactly: `Meter Mic In`, `Meter Mic Out`, `Meter PC In`, `Meter Stream Mix`. `Meter Game Mix` and `Meter HDMI In` are reserved names, registered only when their fields are decoded.
- The controls are read-only and volatile: `SNDRV_CTL_ELEM_ACCESS_READ | SNDRV_CTL_ELEM_ACCESS_VOLATILE`, no `put`.
- The control range and unit are fixed by the decode and copied from `docs/METER_PROTOCOL.md`; the names do not change if the unit is revised.
- `make W=1` must build with no warning from the module.
- Do not change the `0x03` write path, the existing 208 controls, or `zg01_param_read` semantics.
- Raw captures stay out of Git. Fixtures are sanitized or synthetic and carry no personal audio.
- The driver never invents a value: a frame that does not validate leaves the previous snapshot unchanged.

## Review Focus

- A short or malformed `0x83` frame must be rejected without reading past the buffer.
- Disconnect or suspend while a URB is in flight must not resubmit, leak, or touch freed memory.
- `alsactl store`/`restore` must not treat the meter controls as restorable mixer values.
- A decode failure or missing meter must hide the value, never display zero as if it were silence.
- The meter reader must not delay or corrupt the existing control-write path.

## File Structure

- `tools/decode-meters.py` — read normalized usbmon JSONL, extract meter frames, print a column diff, decode a frame. Reference implementation.
- `tests/test-decode-meters.py` — Python tests for extraction and decoding.
- `tests/test-decode-meters.sh` — shell wrapper.
- `tests/fixtures/meters/` — sanitized frame fixtures, `README.md`.
- `docs/METER_PROTOCOL.md` — decoded byte map, scale, frame rate, validation rules.
- `src/zg01_meters.h` — pure frame parser (`static inline`), shared by the module and the userspace test.
- `src/zg01_meters.c` — URB chain, atomics, start/stop.
- `tests/test-zg01-meters.c` — userspace test of the parser against fixtures.
- `tests/test-zg01-meters.sh` — compiles and runs the parser test.
- `src/zg01_control.c` — four kcontrols.
- `src/zg01.h`, `src/zg01_usb.c`, `Makefile` — state, lifecycle, object list.

- [ ] **Step 3: Implement `tools/decode-meters.py`**

```python
#!/usr/bin/env python3
"""Extract and decode ZG01 meter frames from normalized usbmon JSONL."""
from dataclasses import dataclass

METER_HEADER = bytes.fromhex("04f04310043e1402")
METER_LEN = 192
METER_EP = "0x83"


@dataclass
class Frame:
    endpoint: str
    transfer: str
    direction: str
    data: bytes
    time: float


def read_frames(path):
    frames = []
    with open(path, encoding="utf-8") as stream:
        for line in stream:
            row = json.loads(line)
            frames.append(Frame(
                row["endpoint"], row["transfer"], row.get("direction", ""),
                bytes.fromhex(row["data"]), row.get("time", 0.0)))
    return frames


def is_meter_frame(frame):
    return (frame.endpoint == METER_EP and frame.transfer == "bulk"
            and frame.direction == "in" and len(frame.data) == METER_LEN
            and frame.data.startswith(METER_HEADER))


def extract_meter_frames(frames):
    return [f.data for f in frames if is_meter_frame(f)]
```

Add the CLI with `argparse` and `frames FILE` / `decode FILE`; `decode` calls `decode_frame` (Task 2).

### Task 2: Decode the meter map from captures

**Files:**
- Modify: `tools/decode-meters.py`
- Create: `docs/METER_PROTOCOL.md`
- Create: `tests/fixtures/meters/frames.jsonl` (sanitized)
- Modify: `tests/test-decode-meters.py`

**Interfaces:**
- Produces: `decode_frame(data: bytes) -> dict[str, int]` with keys `mic_in`, `mic_out`, `pc_in`, `stream_mix`. `game_mix` and `hdmi_in` are omitted (see the spec's meter scope).
- Produces: `column_stats(frames: list[bytes]) -> list[tuple[int, int, int]]` returning `(offset, min, max)` for each byte that varies.
- Produces: `docs/METER_PROTOCOL.md` with the frame header, length, offsets, widths, endianness, scale, meter names, and validation rules.

**Capture and correlation procedure:**

1. Connect the ZG01 and load the driver.
2. Start `sudo tshark -i usbmonN -w meters.pcapng` or `sudo tcpdump -i usbmonN -w meters.pcap`.
3. Drive one meter at a time with a known signal:
   - MIC IN: a 1 kHz sine into the mic input at −60, −40, −20, −6 and 0 dBFS.
   - MIC OUT: the same signal through the mic chain with GATE/COMP/LIMIT off, then on.
   - GAME: a known stereo signal on HDMI and then USB.
   - VOICE: a known signal on the USB voice output.
   - STREAM: the mixed output with the three sends at known levels.
4. Stop the capture, convert to classic pcap if needed
   (`tshark -r meters.pcapng -F pcap -w meters.pcap`), normalize with
   `python3 tools/normalize-usbmon.py meters.pcap --device B.D > meters.jsonl`.
5. Run `python3 tools/decode-meters.py frames meters.jsonl` and
   `python3 tools/decode-meters.py columns meters.jsonl`.
6. Compare the varying offsets with the known steps. Test 1-byte and
   2-byte little-endian fields; eliminate offsets that only track the
   frame counter or padding.
7. Pin the scale at five known levels. Prefer a linear 0–100 or 0–127 map
   if it fits; otherwise record the curve. Do not invent a dB scale that
   the device does not provide.
8. Write a sanitized fixture with at least four frames: silence, low,
   mid, high, each with the decoded expected values. Keep the fixture
   small; do not commit the capture.

**Done when:** `decode_frame` returns MIC IN, OUT, PC IN and STREAM
values that track the hardware meters within 2 steps (or 1 dB if the
scale is logarithmic) across the five levels, and `docs/METER_PROTOCOL.md`
states the exact offsets, widths, endianness and scale. GAME and HDMI are
documented as undecoded, not fabricated.

- [ ] **Step 1: Add the state and the URB completion**

In `src/zg01_meters.c`, allocate a 512-byte buffer, submit
`usb_rcvbulkpipe(dev->udev, ZG01_PARAM_EP_IN)`, and in the completion:
parse with `zg01_meter_parse`; on success store the four values with
`atomic_set`; on `-ESHUTDOWN`, `-ENOENT` or `dev->disconnecting`, stop;
otherwise resubmit. The URB is allocated once and reused.

of `zg01_disconnect` before the card is freed, and in the error paths
after start. `zg01_meters_stop` calls `usb_kill_urb`, clears `running`,
and frees the URB and buffer.
